# Monthly data refresh runs on GitHub Actions cron, not Airflow

We initially considered Apache Airflow for the monthly ClinicalTrials.gov refresh, but Airflow is normally run as an always-on scheduler + webserver + metadata DB — disproportionate standing infrastructure for a job that fires once a month, and in tension with the low-cost/low-ops stance from ADR 0004 (managed Cloud Composer runs ~$300+/month even at its smallest; self-hosting is cheaper but real ongoing ops). We decided to use a GitHub Actions scheduled workflow (cron trigger) instead, running the existing fetch/transform/load/export/graph-build scripts directly against Snowflake and Neo4j AuraDB (both already internet-reachable) using credentials from GitHub Secrets. This is effectively free at monthly frequency and needs no infrastructure to provision or keep running between refreshes.
